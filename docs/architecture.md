# Implementation notes

`src/model.ts` owns proposal parsing, clean Markdown projections, source mappings, safe-container grouping, and identity-based transformations. It has no Obsidian dependency. It recognizes literal constructs before interpreting proposal delimiters; projections preserve all unrelated source.

Source decorations and Live Preview replacements share one CodeMirror state field. A focused editor reveals source after deliberate selection or native typing inside a comparison. A host document reload clears that editing intent: the remembered cursor cannot suppress a newly arrived agent proposal. Focus changes refresh decorations through a component-owned animation frame; unfocused panes render comparisons. Native table-cell editors never own a full-note comparison. CodeMirror creates widgets for visible content, and the Reading coordinator follows native preview sections rather than rendering every offscreen proposal.

Comparisons have no extra outer vertical margin and retain their original 8px vertical / 12px horizontal padding. Only the coloured left indicators remain; there is no surrounding frame or separator border. Very light panel tints follow the configured deletion/addition backgrounds; changed words retain the stronger highlight. Geometry checks verify the padded layout and compare text at the same content width with clean documents, across both rendered views and all four themes.

Callouts inside comparisons use normal Markdown whitespace instead of inheriting CodeMirror's `break-spaces`. Otherwise the renderer's formatting newlines create empty lines inside Live Preview callouts. The reset is scoped to callouts, preserving surrounding prose layout and native code/preformatted rules. Callout geometry is compared with native callouts in each rendered view, including nested, folded, code, and math content.

`src/render.ts` uses Obsidian's Markdown renderer for both alternatives. References and footnotes render with the complete clean document context before the relevant container is extracted. Each comparison owns its renderer children and asynchronous controls. Text marks respect Unicode grapheme boundaries. Colours and side borders identify the alternatives; side labels remain accessible without visible headings. Only proposals with no visible text hunk get source evidence. A single comparison is its own keyboard anchor. Shared comparisons retain floating numbered proposal anchors for independent or ambiguous changes without reserving space.

Reading comparisons receive no editor reference, focus anchors, or review callbacks. Task inputs are disabled; generated Bases and iframe content are inert. Embedded notes and native hover previews use the same display-only path. A guard prevents recursive processing of a comparison's own rendered Markdown.

The floating toolbar belongs to the anchor's document, including a popout. Rendered comparisons anchor it to the whole block's top right; highlighted words are display-only and cannot relocate it or select an action target. Shared comparisons retain their explicit numbered selectors, with Escape returning focus to the selected anchor. Source decorations retain range-based positioning. The toolbar is appended to the document body only while visible and removed on dismissal. The scrolling note viewport and window constrain its fixed position, keeping it below the pinned review bar. When clamping would cover numbered selectors, the toolbar moves below their row, or beside them if vertical space is insufficient. Scroll, resize, anchor-size changes, mode changes, keyboard focus, and pointer transitions participate in its lifecycle. Its DOM never reserves space in a paragraph or table.

Review actions capture the owning view, file identity, complete buffer snapshot, and exact proposal range. After reading the current disk bytes, the plugin revalidates the snapshot and the view's last loaded data. A stale target is refused; there is no search for similar text. A review uses one CodeMirror history transaction. A later pane selection is not overridden when an asynchronous check finishes.

The review-bar coordinator owns one component per attached full `MarkdownView`, including splits and popouts. Each bar is the first child of its view's content element, outside the native scrolling surfaces. A scoped flex layout reduces only the available viewport height, preserving text widths and native mode visibility. A resize observer requests editor measurement when the bar wraps or disappears. Closed views and document migrations dispose their old component, DOM, listeners, and observer.

Each view reuses its full-note editor's parsed state or caches its Reading source independently. Event-driven updates are coalesced without polling or scanning the vault. Commands and bar buttons share the bulk-resolution method and captured view/file/source guards. File-identity locks disable bulk controls in every pane of the same note while a decision is running; divergent buffers or another active table-cell editor refuse the operation. Reading and read-only panes remove action DOM and listeners entirely. Counts include offscreen proposals, but exclude diagnostics and literal markers. No status-bar item is created.

Obsidian normalizes editor line endings and strips a UTF-8 BOM on a fresh text read. A component-owned override of the public `getViewData()` serialization boundary preserves the original file format while leaving buffer offsets and undo native. Review decisions also resolve the corresponding raw proposal range, preserving the selected arm's own line endings even when the alternatives contain identical text. Compact newline/BOM snapshots keyed by SHA-256 restore those formats through native undo/redo without retaining a complete document per decision. The override is restored only when still owned by this plugin. Mixed line endings and final-newline state have exact tests.

Private host access is limited to guarded CodeMirror ownership and native table-cell closing. On Obsidian 1.14.5, closing the active cell before a root review transaction prevents its separate editor history from intercepting the change. If a future host lacks that guarded operation, the plugin leaves the proposal pending and asks the user to finish cell editing. Native cell-padding changes are tested against an independent native edit.

Build/deployment code lives under `scripts/`. Deployments copy only the three plugin assets, discover existing installations by manifest ID, and never replace settings. The real-app harness verifies a random disposable-vault sentinel, installed asset hashes, and loaded plugin identity before testing. It uses a separate application profile and closes only its spawned instance.
