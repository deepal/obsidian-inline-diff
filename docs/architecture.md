# Implementation notes

`src/model.ts` owns proposal parsing, clean Markdown projections, source mappings, safe-container grouping, and identity-based transformations. It has no Obsidian dependency. It recognizes literal constructs before interpreting proposal delimiters; projections preserve all unrelated source.

Source decorations and Live Preview replacements share one CodeMirror state field. A focused editor reveals source after deliberate selection or native typing inside a comparison. A host document reload clears that editing intent: the remembered cursor cannot suppress a newly arrived agent proposal. Focus changes refresh decorations through a component-owned animation frame; unfocused panes render comparisons. Native table-cell editors never own a full-note comparison. CodeMirror creates widgets for visible content, and the Reading coordinator follows native preview sections rather than rendering every offscreen proposal. Sections processed while detached retain their source mapping until native virtualization attaches them; their render-child lifetime owns cleanup.

A rendering container is separate from an approval decision. Pure `ReviewUnit` records keep the exact proposal and source span; `ReviewHunk` records describe changed source passages, Unicode grapheme boundaries and projected Markdown locations, including table row/column and enclosing token paths. No proposal is split into smaller approval decisions.

`src/render.ts` renders both clean projections through Obsidian. `src/unified.ts` locates each complete proposal arm and moves its native DOM into a stacked Before/After pair at that source position. Word differences are highlights within separate complete alternatives. Unmarked paragraphs, cells, items and callout content remain in the shared native container. Whole-structure proposals intentionally retain two complete structures. Native nodes are moved rather than cloned so delayed renderer children retain their ownership.

`ReviewPlacement` retains the unit, owning Markdown token context, both rendered side ranges and the comparison anchor. Complete block locations come from Markdown token maps and matching native container ordinals. Inline boundaries use two detached native renders with unique tokens at exact projected offsets. Removing the tokens must reproduce the original semantic tree before boundaries transfer by DOM paths and offsets. Syntactically inseparable emphasis, tag and link boundaries retain the small native syntax context required to render both alternatives; empty emphasis can make its delimiters literal. Empty probe paragraphs are removed and adjacent text nodes normalized before comparison. Ownership never comes from matching displayed words. Ambiguous mappings fail closed with a diagnostic and leave source proposals pending. At most four native renders materialize a group, independent of proposal count; references and footnotes retain full-document context.

Phrasing contexts use span wrappers with block styling; cells and callouts use flow containers. List-item and table-row rewrites use valid local list/table shells and proxy items/rows. Comparison panels retain their previous padding, coloured left borders, subtle backgrounds and empty-side placeholders. Unicode graphemes, native math/SVG glyph trees, formatting and structural whitespace survive highlighting.

A component-owned registry maps each exact proposal identity to one complete comparison pair. The pair is the navigation target and receives the temporary accent outline. Hunks describe changed passages for highlighting; they do not split a comparison or create extra stops. Invisible edits receive local source evidence in each side. Stale asynchronous work cannot register targets, and disposal clears the registry.

The floating toolbar belongs to the comparison's document, including popouts. Hovering either side captures the same complete proposal; Enter/Space reaches the controls and Escape restores comparison focus. The toolbar stays outside note layout and clamps to the owning viewport below the pinned review bar. All observers, scopes and scheduled work follow component lifetimes. Numbered block selectors remain removed.

Reading, embeds and read-only editors receive no mutation callbacks. Native writing controls are disabled, and Bases/iframes remain inert. Folded callouts containing rendered proposals open for review. Renderer children remain owned until their comparison is disposed; CodeMirror and native Reading sections continue to control virtualization.

Review actions capture the owning view, file identity, complete buffer snapshot, and exact proposal range. After reading the current disk bytes, the plugin revalidates the snapshot and the view's last loaded data. A stale target is refused; there is no search for similar text. A review uses one CodeMirror history transaction. Its exact validated transform bypasses native typing filters so Obsidian cannot renumber unrelated ordered-list items during approval; normal editor typing retains its native filters. A later pane selection is not overridden when an asynchronous check finishes.

The review-bar coordinator owns one component per attached full `MarkdownView`, including splits and popouts. Each bar is the first child of its view's content element, outside the native scrolling surfaces. A scoped flex layout reduces only the available viewport height, preserving text widths and native mode visibility. A resize observer requests editor measurement when the bar wraps or disappears. Closed views and document migrations dispose their old component, DOM, listeners, and observer.

Each view reuses its full-note editor's parsed state or caches its Reading source independently. Event-driven updates are coalesced without polling or scanning the vault. Commands and bar buttons share the bulk-resolution method and captured view/file/source guards. File-identity locks disable controls in every pane of the same note while a decision is running; divergent buffers or another active table-cell editor refuse the operation. Reading and read-only panes remove mutation controls and listeners entirely, retaining navigation. Counts include offscreen proposals, but exclude diagnostics and literal markers. No status-bar item is created.

Each bar owns a navigation controller and its listeners, pending render waits, and temporary outline. The complete parsed source orders individual proposals, including identical proposals and multiple comparisons in one cell. Coordinates normalize BOM and CRLF to match editor and renderer offsets, while stale-target guards retain the original source snapshot. The first step uses the source position at the viewport's top; subsequent steps remember the selected proposal and wrap. Manual scrolling, source/file changes, and mode changes reset that session. Navigation-generated scroll events are ignored. One pending proposal disables both arrows; no proposals hide the bar.

Source and Live Preview navigation dispatch scrolling and targeted unfolding effects without changing the selection or document. A comparison-reveal effect clears editing intent while preserving the caret, so Live Preview continues to show rendered comparisons. Reading uses the native ephemeral line-navigation path to reveal virtualized sections and folded headings, then resolves the exact proposal registry anchor. On settling, its native whole-section flash is removed so only the comparison pair receives the accent outline. A bounded, cancellable settling pass aligns the owning pane's vertical scroller and any inner horizontal table scroller, revalidating file, source, mode, and attachment before every adjustment. Controls disable while settling and restore the initiating arrow's focus only if the user has not moved elsewhere. An independent accessible status announces the selected proposal; command-palette navigation retains its existing cursor-based behaviour.

Obsidian normalizes editor line endings and strips a UTF-8 BOM on a fresh text read. A component-owned override of the public `getViewData()` serialization boundary preserves the original file format while leaving buffer offsets and undo native. Review decisions also resolve the corresponding raw proposal range, preserving the selected arm's own line endings even when the alternatives contain identical text. Compact newline/BOM snapshots keyed by SHA-256 restore those formats through native undo/redo without retaining a complete document per decision. The override is restored only when still owned by this plugin. Mixed line endings and final-newline state have exact tests.

Private host access is limited to guarded CodeMirror ownership and native table-cell closing. On Obsidian 1.14.5, closing the active cell before a root review transaction prevents its separate editor history from intercepting the change. If a future host lacks that guarded operation, the plugin leaves the proposal pending and asks the user to finish cell editing. Native cell-padding changes are tested against an independent native edit.

Build/deployment code lives under `scripts/`. Deployments copy only the three plugin assets, discover existing installations by manifest ID, and never replace settings. The real-app harness verifies a random disposable-vault sentinel, installed asset hashes, and loaded plugin identity before testing. It uses a separate application profile and closes only its spawned instance.
